Agent③ · Fault Diagnosis

故障诊断流程

设备故障 → 输入解析 → 三轨并行匹配 → 证据组装 → LLM 报告合成 → 充分性判断 → 追问循环 / 工单路由。 迁移自 EduAgent 课件「06-试卷批改 Agent」的三轨并行 + Human-in-the-Loop 架构。

负责 ⑤号 节点 9 追问上限 2 轮 入口 diagnose()

1主流程（9 节点）

点击节点查看实现细节。整体为线性链 + 追问循环，checkpointer（MemorySaver）支撑 interrupt 暂停/恢复。

1
parse_input 输入解析
提取故障码（正则 E001）· 现象关键词（去停用词）· 图片降级链（视觉 → OCR → 置空）
故障码优先取入参，其次从文本正则提取并转大写；现象按标点切分、过滤停用词； 图片一期置空 image_desc，不阻断流程。
2
load_diag_tree 加载诊断树 + 知识库
懒加载诊断树（YAML）· 调 KBClient 混合检索（hybrid_retrieve）· ③ 不可用时优雅降级
查询串 = 故障码 + 用户原文；知识库异常被捕获并记录，kb_hits=[] 继续走诊断树，不中断主流程。
3
run_diag_tracks 三轨并行
asyncio.gather(return_exceptions=True) —— 任一轨失败不影响其他轨
三轨并行启动，异常作为返回值处理：失败的轨置空，其余正常写入 State。对齐 exam 的 run_three_tracks_node 容错模式。

轨① 精确匹配 规则引擎

故障码查表命中诊断树节点。
确定性匹配，无 LLM 调用。

置信度 0.95

轨② 模糊匹配 覆盖率

现象关键词与节点现象的覆盖率（命中数 ÷ 输入数），≥ 阈值 0.6。

置信度 ≥ 0.6

轨③ LLM 推理 兜底假设

树未命中时由 LLM 生成 2-3 个候选原因假设 + 置信度。

置信度 ≤ 0.4
4
assemble_context 证据组装
三轨结果 + kb_hits 前 3 条 → 格式化为 LLM 上下文
输出 evidence_context：诊断树/推理命中 + 知识库片段，供报告生成节点使用。
5
generate_report LLM 报告合成
Think 推理（REASON_PROMPT）→ 结构化输出（DIAGNOSIS_REPORT_PROMPT）→ Pydantic 校验
树命中时置信度封顶 0.95；无树命中封顶 0.4。LLM 失败/JSON 解析失败 → 模板兜底（直接用命中节点数据渲染）。
6
check_sufficiency 充分性判断
置信度 ≥ 0.7 且 need_ticket 已定 → 直接路由；否则 → 追问
条件路由 _route_after_check：有 clarify_question 走追问路径，否则走 route_next。
低置信 / 信息不足
7
ask_clarify HitL 暂停
interrupt() 冻结图执行，State 存 MemorySaver，等用户回答
优先用诊断树节点预设问题；无预设则 LLM 生成（CLARIFY_PROMPT）。对齐 exam 的 teacher_review 节点。
8
apply_clarify_answer 合并回答
合并用户补充 → 更新 fault_code / phenomena → turn+1 → 回到轨 3 重新诊断
对齐 exam 的 apply_teacher_decision：清空旧报告与三轨结果，重新执行诊断链。最多 2 轮。
置信足够
9
route_next 结果路由
need_ticket=true → 交 ④ Supervisor → ①号 create_ticket；否则返回用户
⑤ 不直接调用 ①号：只返回 structured_output（诊断报告），由 Supervisor 决定下一步。
追问循环 × ≤2 轮
ask_clarify → apply_clarify_answer → run_diag_tracks

2降级策略

每一条链路都有兜底，任何单点故障都不会让诊断流程挂死。

故障场景降级行为级别
知识库（③）不可用 跳过检索，kb_hits=[]，继续走诊断树匹配 降级
诊断树无命中 LLM 兜底推理，置信度压制 ≤ 0.4 降级
LLM 超时 / JSON 解析失败 模板兜底：直接渲染命中节点的 causes / solutions，标记 _template=true 降级
图片无法解析 image_desc 置空，提示用户补充文字描述 继续
追问超 2 轮仍未确认 强制出报告 / 转人工，不再循环 继续
全链路故障 返回「无法自动诊断，建议人工介入」+ need_ticket=true（保底不挂死） 保底
